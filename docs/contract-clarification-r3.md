# Task 1215 — controller contract clarification R3 (2026-10-10)
Technical decision inside existing implementation authority. This supersedes only the listed ambiguities in R2; no security or live acceptance gate is waived. L1/L2/L3 are not integrated into the product yet.

1. Request identity is the enclosing requests map key, derived r:<request_id> or n:<nonce>. Do not duplicate a key property in the stored Request. L1 and L2 agree on this. Remove key from the R2 Request-field listing, preserve strict unknown-property rejection. Tests must use an independent key derivation when inserting/looking up records. Do not weaken tests for invalid unknown keys or duplicate nonces.
2. Counter and quarantine names are lower-case reason codes matching ^[a-z][a-z0-9_]{0,63}$, at most64. Fault-injection errno labels remain uppercase; the counter chosen to witness a commit must be a valid distinct lower-case reason. Test uppercase-name rejection explicitly if existing invalid-input coverage lacks it.
3. Cleanup must remove only known store-created temp names, never generic .*\.tmp artifacts. Pin .state.json.<16hex>.tmp, .credential.json.<16hex>.tmp and replies/.<32hex>-<64hex>.json.<16hex>.tmp. Assert unknown similar names survive. This narrows cleanup authority rather than broadening it to satisfy a test.
4. Binding mismatch is tested with a structurally valid stored state under its original binding. Invalid nested inbox ids remain STORE_CORRUPT. Test origin/prefix changes without making the input corrupt first.
5. POSIX paths with a fake win32 platform do not exercise native Windows filesystems. Do not claim Windows support from such a fixture. Correct the simulation only if a coherent path/filesystem seam is available; otherwise make that impossible platform fixture explicitly NOTRUN and preserve/add the real win32-only test. Native Windows credential-storage acceptance remains open.
6. Health/list-targets are read-only diagnostics and do not rotate/recover/create inboxes. Recovery is exercised by send/receipt/readReply as implemented in the L2 public contract. Any corresponding future HTTP test correction must preserve its actual recovery assertion, not drop it.
